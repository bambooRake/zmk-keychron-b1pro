### ⚠ PID 不一致の決定的事実

実機 PID = **`0x071C`**
我々の build (`keychron_b1_jis.conf`) の `CONFIG_USB_DEVICE_PID` = **`0x0713`**

**= 別ハードウェア向けの firmware を build していた**ことが確定。

- **`PID 0x0713`**: 旧 B1 Pro (公開ソースの `keychron_b1_jis` shield が想定するハード)
- **`PID 0x071C`**: 実機 (B1 Pro 25 / 2025 HW revision、別マトリクスの可能性)

公開ソースには **PID 0x071C 用の shield 定義が存在しない**。これが alphabet キー誤動作の根本原因。
Device version `v1.0.1-ZK` も特殊 build を示唆 (公式リリース番号と異なる ZK 版)。

## なぜ保留か

我々が build した firmware (および公式 v1.0.5) で、**alphabet キーが正しく入力されない** バグに遭遇：

| 物理 | 期待 | 実際 |
|---|---|---|
| A | a | r |
| S | s | i |
| D | d | o |
| Q | q | ¥ (INT3) |
| ... | ... | ... |

切り分け結果：

- ✅ **公式 v1.0.0** (b1pro25 build, 2025-08-21): **正常動作**
- ❌ **公式 v1.0.5** (b1pro build, 2025-08-21): 同じバグ
- ❌ **我々の build** (公開ソース ベース、各種 patch 込み): 同じバグ

**真因:** Keychron 公開リポジトリ (https://github.com/Keychron/zmk, branch `keychron_bpro`) の **最終 commit が 2025-02-08**。一方、firmware は 2025-08-21 build。**約半年分の Keychron 内部修正が未公開**。

公開ソースから build した firmware は v1.0.5 相当で、alphabet が壊れる regression を含む。

#### 削除作業の優先順位

1. **E (kscan revert)** を真っ先に剥がす ← 最も介入度が高く、副作用も大きい
2. **D の関連 stub** を E に応じて削除
3. **A, B (EEPROM 系 patch)** を minimal `&kp` で動作確認しつつ剥がす
4. **H (conf debug 系)** を整理
5. **F** は新ソースで既に直ってれば自動的に不要
6. **C, G** は LalaPad 移植本来に必要なので最後まで残す可能性が高い

#### 各 patch を剥がす前後で必ず動作確認

- minimal `&kp X` keymap で alphabet 全部正常 → patch 剥がしても OK
- 何か壊れたら直近で剥がした patch を戻す

## 教訓

- **作業開始前に必ず実機 PID を確認**して、ターゲット shield の `CONFIG_USB_DEVICE_PID` と一致するか検証する。一致しなければ別 HW 用 shield を build してることになり、何をやっても直らない。
- 商品名 (例「B1 Pro JIS」) だけでは HW revision を判別できない。Keychron は同名で複数 HW を持ち、ファイル名の "25" 等の suffix で区別している。
- 実機 PID は **Keychron Launcher** (https://launcher.keychron.com/) の情報パネル or Windows の `Get-PnpDeviceProperty` で取得：
  ```powershell
  Get-PnpDevice -PresentOnly | Where-Object InstanceId -like '*VID_3434*' | Select-Object FriendlyName, InstanceId
  ```
- ZMK fork に依存する商用 keyboard は **公開ソースが production firmware と同期してない** リスクあり
- バイナリ書き換え後は **ピンホールリセット** が確実な復旧経路
- Bus reported device description (`DEVPKEY_Device_BusReportedDeviceDesc`) で書き込み内容（製品名）確認できる
- Keychron `set_zmk_keymap()` 経路で EEPROM 由来の上書きが起きるのは要注意
